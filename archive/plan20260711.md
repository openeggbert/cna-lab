  store exists but cave seeding itself was never implemented for this
  specific "vertical hint" use).

  file-cache→region-store migration tool; both genuinely unimplemented.

  observed; hasn't been.

## Map mechanism (M-series) — planet-scale procedural map

> **Goal:** develop the mechanism to generate a **planet-Earth-scale map** (≈510 M km²,
> side ≈ 22,585 km) using a **quadtree LOD pyramid** (factor 2, ~18 levels), **lazy Lua
> generation** (a tile is generated only when the player navigates/zooms into it), **SQLite
> persistence**, **geo + altitude-indexed 3D model streaming** (only models within a 3D radius
> of the player are loaded), **procedural naming** (continents/countries/cities/streets/
> mountains/rivers), and a **zoomable map UI**.
>
> **Design doc:** `map.md`. "M" = map. Tasks are ordered by dependency; mark `[x]` when done.
> The **map mechanism is the foundation** — the focus for the foreseeable future. Heavy 3D
> model work (MAP11) follows once the map LOD is solid.
>
> **Architecture rules carry over:** offline-first (no AI/network), non-reproducible
> (time entropy + persisted artifacts, never "same seed forever"), Lua sandbox unchanged,
> 64 m chunk + `ChunkCoord::from_world` untouched (map sits *above* chunks), MC3/MCB
> per-chunk scene format untouched, SPDX header on every new file.
>
> **Code layout (Map subsystem):** all M-series C++ code lives in **`include/Map/`** +
> **`src/Map/`** in namespace **`MeshWorld::Map`** (tests stay in `tests/`). Task lines below
> write paths flat for brevity (e.g. `include/TileCoord.hpp`) but mean the `Map/` location
> (`include/Map/TileCoord.hpp`). Include as `#include "Map/TileCoord.hpp"`.

### MAP0 — Vertical slice first (DO THIS BEFORE COMMITTING TO THE REST) ⟢

> CLI driver (no map UI yet), no 3D model store/sharding (render the chunk via the existing
> MC3 path), no altitude indexing, no hydrology/political/naming breadth. Simplified terrain
> is fine — the point is the *descent + consistency*, not pretty geography.
>
> **Tasks that make up the slice** (subset of the milestones below — ~60 of 228, <30%):
> - **MAP1:** M001, M003, M004, M005, M006, M007, M008, M010, M011, M013, M015

> - **MAP13 (driver):** M203, M204, M211
>
> **GREEN-LIGHT GATE — only proceed to the full M-series if ALL hold:**
> 1. Descending planet→chunk for a random location produces a renderable chunk.
> 2. Re-descending to the **same** location yields an **identical** result (persistence works).
> 3. Elevation/biome are **continuous across the descent** (child matches parent at shared edges;

### MAP16 — Biome taxonomy expansion (maximum biome diversity)

Generated 2026-07-10 from `docs/map-generator-audit.md`, at explicit user priority:
"regarding biomes I want to have the maximum possible number of biomes." `ZoneType`
today has 12 values (`city, jungle, desert, forest, ocean, mountain, tundra, swamp,
cave, meadow, beach, empty`), of which `BiomeClassifier::classify()` only ever
produces 8 from real terrain data (city/cave/beach/empty come from other logic).
This section grows the enum by 40 real, climate-science-grounded biomes (Whittaker
biome diagram + Köppen climate classes + standard coastal/geologic biome types),
reaching 52 total — the practical ceiling for a classifier driven purely by
`(elevation_m, temperature_c, moisture, sea_level_m)`; further subdivision would need
new input signals (wind exposure, soil type, micro-noise) and is intentionally left
for a future pass rather than invented here just to inflate the count.

New `ZoneType` values, grouped by climate family (see M235 for exact enum order):

- Grassland / dry-climate (5): `savanna, steppe, prairie, chaparral, shrubland`
- Forest variants (8): `taiga, temperate_rainforest, mixed_forest, cloud_forest,
  mangrove, bamboo_forest, riparian_forest, tropical_dry_forest`
- Wetland variants (4): `marsh, floodplain, bog, muskeg`
- Desert / arid variants (8): `dunes, rocky_desert, cold_desert, salt_flat, badlands,
  mesa, canyon, oasis`
- Cold / high-elevation (4): `glacier, permafrost, alpine_meadow, ice_cap`
- Volcanic / geothermal (4): `volcanic, geothermal, ash_plain, volcanic_island`
- Aquatic / coastal (7): `coral_reef, kelp_forest, deep_ocean, lagoon, fjord,
  tidal_flat, sea_cliff`

Every new value needs the same 6 touch points the 12 existing ones already have:
`include/ZoneType.hpp` (enum + `to_string()` + `zone_from_string()`),
`include/PlanetMapLogic.hpp`/`src/PlanetMapLogic.cpp` (`ZONE_NAMES`, `zone_rgb_color()`,
`zone_ascii_char()`, `biome_histogram()` sizing is automatic via `ZONE_NAMES.size()`),
`src/WorldMap.cpp` (`WorldMap::zone_color()`), `src/MapValidator.cpp`'s range check
(automatic as long as `empty` stays the last enum value), and `src/tools/print_map.cpp`
(`zone_char()`, needs a new unique ASCII letter per value).
