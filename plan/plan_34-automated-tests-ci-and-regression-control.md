# 34. Automated tests, CI, and regression control

[Back to master plan](../plan.md)

Protect deterministic systems, converters, builds, and representative gameplay flows at Mafia-1 fidelity (district loading, simplified traffic/police/pedestrian AI, EasyGL as the shipped backend) rather than a modern open-world test matrix.

- [x] **IG-34-001 P0** — Keep core tests window-free and fast. *(`iron_gang_core_tests` creates no window and no graphics device -- anything needing one lives in the renderer and is exercised by `--smoke` runs instead. The whole 12-test CTest suite runs in about 25 seconds, of which the core tests are ~0.2 s; that is what makes it reasonable to run the full suite after every change, which this project's sessions do.)*

- [ ] **IG-34-006 P1** — Add unit tests for every parser, state machine, serializer, and deterministic controller. *(Partial, and the honest gaps are named. Covered: five parsers (mission, campaign, config, vehicle, settings) plus the JSON bound layer and the mission expression grammar; five state machines (mission graph, police, cutscene, traffic signal, autosave scheduler); two serializers (save, settings); and the deterministic controllers `Locomotion`, `VehicleDamage`, `TrafficVehicle`, `Pedestrian`, `SimulationClock`, `RandomSource`, `MenuModel`, `InputBindings`. **Not covered:** `PlayerController`/`VehicleController` are tested only through physics or not at all, and the renderer's animation state has no test because it needs a graphics device (IG-34-014).)*
- [x] **IG-34-007 P1** — Add property tests for IDs, package bounds, and save round trips. *(`TestSaveRoundTripsRandomSnapshots` puts 250 randomly generated snapshots through write/read and compares every field: ids, positions, angles, speeds, integrity, campaign progress, both halves of a checkpoint, and every mission variable. Values are drawn from a deterministic `RandomSource` (plan_04 IG-04-011), so a failure is reproducible from the seed rather than a story about a run nobody can repeat. String values are drawn from fragments chosen to poke at the line format -- `=`, `:`, `;`, quotes, leading/trailing spaces, non-ASCII bytes, emoji. **The first version of this test was hollow**: it compared `ToText()` to `ToText()`, which passes even when the formatting loses precision on both sides equally -- proven by mutating float output to two decimals and watching the test stay green. It now compares typed values, and the same mutation fails it (`wrote -31109.312500, read -31109.310547`). Package/ID bounds are covered separately by the mission-expression and JSON-bound tests (plan_36 IG-36-002).)*
- [x] **IG-34-008 P1** — Add malformed asset/save/mission-data input tests. *(Mission data: 24 rejection cases in `TestMissionValidationRejectsMalformedData` plus 20 malformed expressions in `TestMissionExpressionRejectsMalformedInput`. Saves: `TestSaveFormatRobustness` (flipped byte, truncation, missing checksum, future version, missing fields, leftover temporary, read-only directory). Campaign: eleven cases including two cycle shapes. Config/vehicle/settings: wrong types, out-of-range values, unknown keys, malformed JSON. Data files: over-size, invalid UTF-8, and over-deep nesting, each rejected before the parser runs.)*
- [ ] **IG-34-009 P1** — Add fixed-input gameplay scenario tests.
- [x] **IG-34-010 P1** — Add mission happy-path, skip, fail, retry, save, and load tests. *(Happy path: `TestMissionFlow`, `TestMissionLoadsCommittedFile`, `TestCountrysideMissionRunsAndFailsOnAWreck`. Skip: `TestCutsceneSkipDoesNotBlockMissionProgression`. Fail and retry: `TestMissionCheckpointRetryAndFailureReason` and `TestPrologueFailsAndRetriesUnderPoliceChase`, which drives the committed mission against the real `PoliceSystem`. Save and load: `TestSaveLoadMidMissionPlaythrough`, `TestMissionVariablesSurviveSaveLoad`, `TestMissionCheckpointSurvivesSaveLoad`, `TestCampaignProgressSurvivesSaveLoad`.)*
- [ ] **IG-34-011 P1** — Add district load/unload and cancellation tests. *(Partial: `TestDistrictTransition` covers two full round trips and asserts the physics body count returns exactly to where it started each time a district is revisited -- which is what catches a leak on unload. `TestDistrictTransitionPreservesMissionState` covers the mission surviving a transition. **Cancellation is untested because it does not exist**: `DistrictManager` has no way to abort a transition in progress.)*
- [x] **IG-34-012 P1** — Add simplified-traffic lane-following and signal-compliance scenarios (no deadlock-avoidance/intersection-reservation testing — that system doesn't exist by design). *(Lane following and braking: `TestTrafficVehicleAcceleratesAndBrakes` and `TestLaneClearanceSeesOnlyWhatIsAhead`. Signal compliance: `TestTrafficSignalCyclesAndOpposesItself`, including a vehicle braking to a halt for a close obstacle and pulling away when it clears -- which is how a red light is modelled (plan_21 IG-21-003) -- and the two invariants that matter at a crossing: never both directions moving, and both directions do get a green.)*
