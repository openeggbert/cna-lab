# 24. Mission framework and scripting

[Back to master plan](../plan.md)

Represent missions as versioned, testable state graphs, data-driven enough to carry a
15-20 mission campaign across multiple districts without becoming unmanageable. Logic
that cannot be expressed as declarative data uses a small, engine-evaluated
condition/action expression syntax, not a general-purpose sandboxed scripting language
(no embedded Lua VM, no script API surface to secure).

- [x] **IG-24-013 P1** — Create a small condition/action expression syntax (comparisons, boolean combinators, arithmetic on mission variables) for logic not expressible as declarative data. This is evaluated directly by the engine; it is explicitly not a general-purpose embedded scripting language and has no sandboxing/API-surface project attached to it. *(`MissionExpression` (`include/IronGang/Missions/MissionExpression.hpp`, `src/Missions/MissionExpression.cpp`): tokenizer, recursive-descent parser, static type check, and evaluator over a flat node array. Supports `|| && ! == != < <= > >= + - * /`, unary minus, parentheses, int/float/bool/single-quoted-string literals, and identifiers resolving to declared facts or variables. Chained comparison is rejected rather than silently reinterpreted; `&&`/`||` short-circuit; int/float mix promotes to float. There are no statements, calls, loops, assignments, or engine API reachable from an expression, so the non-goal holds by construction. Mission files use it under `"when"` (`"condition"` remains the version-1 spelling). Documented in `docs/mission-scripting.md`.)*
- [x] **IG-24-014 P1** — Enforce evaluation limits (max expression depth/step count, no recursion) so a malformed mission file cannot hang or corrupt engine state. *(Source length 512, tokens 128, operations 96, nesting depth 16, evaluation steps 256, variables per mission 64, entry actions per state 16 -- all named constants in `MissionExpression.hpp`/`MissionContext.hpp`/`MissionDefinition.hpp`, all enforced with an actionable message. Recursion is impossible: the grammar has no calls, and parse depth is capped before the stack can grow. Division by zero is an evaluation error rather than an infinity. State corruption is prevented by type-checking every expression at load: a mission that would misbehave does not load at all. Verified by `TestMissionExpressionRejectsMalformedInput` (20 malformed sources plus the length/depth/token limits and the divide-by-zero path).)*

- [x] **IG-24-029 P1** — Define save/checkpoint serialization and restoration for in-progress mission state. *(State: `SaveGame`'s existing `mission_state` int round-trips through `PrototypeMissionState`. Variables: `SaveSnapshot::missionVariables` is written as one `mission_var.<name>=<type>:<value>` line per variable (so a string value may contain any character except a newline) and restored through `PrototypeMission::ApplyVariables()`. Restoring deliberately does **not** re-run entry actions -- the run being resumed already did -- which is why `SetState()` and `Reset()` are separate. `MissionValue::ToText()`/`Parse()` round-trip every type exactly (float uses the shortest round-trip form). Verified by `TestMissionVariablesSurviveSaveLoad`. Checkpoint-specific semantics beyond a plain save remain IG-24-010/041-045.)*

## Condition/action expression evaluator

- [x] **IG-24-031 P1** — Define the scope and public API of the condition/action expression evaluator described in IG-24-013/IG-24-014. *(`MissionExpression.hpp`'s header comment states the grammar, the non-goals, and every limit; the public API is `Compile(source, context, out, error)` / `GetResultType()` / `Evaluate()` / `EvaluateBool()` / `IsEmpty()` / `GetSource()`. `MissionContext` is the accompanying symbol table (facts vs variables). Compilation is separated from evaluation on purpose: types are resolved once at load, values every frame.)*
- [x] **IG-24-032 P1** — Implement the smallest deterministic reference path: evaluate one condition, execute one action. *(The committed `assets/missions/prologue.mission.json` is that path end to end: `"when": "player_vehicle_distance <= handover_radius"` evaluates a fact against a mission variable, and `{"action": "set", "variable": "cargo_secured", "value": "true"}` executes on entry. `TestMissionEntryActionsRunOncePerEntry` and `TestMissionExpressionEvaluatesTypedOperations` cover it deterministically; the `--profile-scenario mission` run drives it through the real game loop.)*
- [x] **IG-24-033 P1** — Add input validation, depth/step limits, and actionable failure reporting for malformed expressions. *(Every compile error names the problem and a 1-based column, e.g. `unknown identifier "foo" (not a declared mission fact or variable) at column 5`; the loader prefixes the mission state and file. Type errors are reported with both operand types. Limits as in IG-24-014. Verified by `TestMissionExpressionRejectsMalformedInput` and by the 17 malformed-file cases in `TestMissionValidationRejectsMalformedData`.)*
