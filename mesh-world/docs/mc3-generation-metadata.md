# MeshWorld — MC3 Generation Metadata

Every `.mc3.xml` file generated by MeshWorld includes a `<metadata>` element as the first child of `<mc3>`. This metadata identifies what produced the file, under what variation, and when.

**2026-07-11 correction**: the field names below (`generator_name`, `variation`,
`from_context()`) had drifted from the real `include/GenerationMetadata.hpp`
struct (`generator_id`, `variation_input`, `from_chunk_context()` — plus
`generator_version`/`generator_language`/`category`, not documented here
before). Fixed below. Separately: this C++ struct is what C++ chunk
generators use; every Lua generator instead calls `scene:setMetadata({...})`
directly with its own nested shape (`generator={id=..., version=..., category=...,
language="lua"}, object={...}, generation={variationInput=...}` — see any file
under `generators/lua/`), which `MC3Validator.cpp` also accepts (it checks for
either a nested `generator.id` or a flat `generator_id` key). Both are real,
both are validated; they're just two different, both-supported shapes, not a bug.

## Format

```xml
<?xml version="1.0" encoding="UTF-8"?>
<mc3 version="1.0" model="chunk_9_9">
  <metadata format="json" type="generation"><![CDATA[
{
  "generator_name": "ParkGenerator",
  "variation": 1234567890,
  "style": "central_europe_small_city",
  "zone": "city",
  "region": "park",
  "meshworld_version": "0.1",
  "generated_at": "2026-06-23T14:30:00Z",
  "chunk_x": 9,
  "chunk_y": 9,
  "chunk_size_m": 64.0,
  "ai_assisted": false
}
  ]]></metadata>

  <objects>
    <!-- ... -->
  </objects>
</mc3>
```

## Fields

| Field | Type | Description |
|-------|------|-------------|
| `generator_id` | string | Id of the top-level generator, e.g. `"cpp.chunk.park"` |
| `generator_version` | string | Generator's own semver-ish version, e.g. `"0.1.0"` |
| `generator_language` | string | `"cpp"` or `"lua"` |
| `category` | string | `"chunk"`, `"object"`, `"zone"`, `"building"`, `"map"`, ... |
| `variation_input` | uint64 | Value of `ChunkContext::seed` at generation time. Drives procedural variety. Not a reproducibility guarantee. |
| `style` | string | World style string from `WorldConfig`, e.g. `"central_europe_small_city"` |
| `zone` | string | ZoneType as string, e.g. `"city"`, `"forest"` |
| `region` | string | RegionType as string, e.g. `"park"`, `"road"` |
| `meshworld_version` | string | MeshWorld library version, e.g. `"0.1"` |
| `generated_at` | string | ISO 8601 UTC timestamp of generation |
| `chunk_x` | int | Chunk X grid coordinate |
| `chunk_y` | int | Chunk Y grid coordinate |
| `chunk_size_m` | float | Chunk size in meters (usually 64.0) |
| `ai_assisted` | bool | True if an AI call modified the output; false for pure C++ procedural output |

## C++ struct

```cpp
// include/GenerationMetadata.hpp (real, as of 2026-07-11)
struct GenerationMetadata {
    std::string generator_id;
    std::string generator_version{"0.1.0"};
    std::string generator_language{"cpp"};  // "cpp" or "lua"
    std::string category;                   // "chunk", "object", "zone", "building", "map"

    uint64_t    variation_input{0};
    std::string style;
    std::string zone;
    std::string region;
    std::string meshworld_version{"0.1"};
    std::string generated_at;   // filled automatically with current UTC time
    int         chunk_x{0};
    int         chunk_y{0};
    float       chunk_size_m{64.0f};
    bool        ai_assisted{false};

    std::string to_json() const;

    static GenerationMetadata from_chunk_context(
        const ChunkContext& ctx,
        const std::string& generator_id,
        const std::string& category = "chunk");
};
```

## MC3Writer integration

`MC3Writer` gains a `metadata()` method called at the top of every `generate()` function:

```cpp
std::string ParkGenerator::generate(const ChunkContext& ctx) {
    MC3Writer w(ctx);
    w.metadata(GenerationMetadata::from_context(ctx, "ParkGenerator"));
    // ... rest of generation ...
    return w.build();
}
```

`w.metadata(...)` inserts the `<metadata>` element before `<objects>` in the output.

## Why CDATA

The JSON value is wrapped in `<![CDATA[...]]>` to avoid any need for XML-escaping the JSON. Downstream parsers must strip CDATA delimiters before parsing the JSON.

## Variation policy

`variation` in the metadata is the `ChunkContext::seed` value. It is NOT a guarantee that the same variation will always produce the same output:

- Generator logic may change across MeshWorld versions.
- Object generator composition adds new objects.
- Style system changes alter materials.

The canonical output is the **cached `.mc3.xml` / `.mcb` file**. If you need reproducible output, cache the generated files — do not rely on re-generating from variation values across versions.

## AI-assisted metadata

When the optional Claude API adapter (M18) modifies a chunk, `ai_assisted` is set to `true`. The JSON may include additional fields:

```json
{
  "generator_name": "ParkGenerator",
  "variation": 999,
  "ai_assisted": true,
  "ai_model": "claude-sonnet-4-6",
  "ai_prompt_version": "1",
  "ai_retry_count": 0
}
```

AI-generated content is validated by `MC3Validator` before being written to cache.
