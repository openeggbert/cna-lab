# 30. Developer tools and editors

[Back to master plan](../plan.md)

No **second, Iron Gang-specific** editor suite is built. Spatial content (buildings, roads, interiors, props, collision, trigger/mission-marker areas) is authored visually in **Mesh Craft**, which is already a real 3D scene editor (viewport, orbit camera, gizmos, CSG, extrude-along-path, scene hierarchy/properties panels, Walk Mode, and bounded live event-binding preview) — nothing here duplicates that. Non-spatial content (mission state graphs, dialogue) is hand-written JSON/XML/text data, checked by command-line validation scripts. At most one small in-game debug/mission-state view tool is in scope, purely for runtime debugging, not authoring.

- [x] **IG-30-012 P2** — Create deterministic input recording and playback for QA repro cases. *(`InputScript`/`InputScriptRecorder` (`include/IronGang/Input/InputScript.hpp`, `src/Input/InputScript.cpp`) plus `--play-input` / `--record-input` / `--record-input-id`. A script names **actions**, not keys, so a rebind cannot invalidate a repro, and is keyed on the **simulation update** rather than the draw frame -- the fixed 60 Hz step is identical everywhere, while how many frames a run draws depends on how fast it renders. Recording is sparse: one step per change, so an idle minute costs one step rather than 3600. Playback *replaces* the keyboard rather than merging with it, and with no `--smoke` bound the run ends when the script does, which is what makes a repro's length reproducible. Paired with `--screenshot-update <n>` (added here) a specific scripted moment can be captured. Committed repro: `tests/input-scripts/prologue_opening.inputscript.json`, which skips the cutscene, walks the player to the sedan, and enters it. New CTest `iron_gang_input_script_tests` is the first test in the repository that presses a key; mutation-checked. Not done: no mouse/gamepad axis recording -- the game has no such input path yet.)*
- [x] **IG-30-013 P2** — Create screenshot/reference capture automation for regression review. *(`--screenshot <path>` / `--screenshot-frame <n>` capture one draw frame as an RGBA PNG plus a `<path>.summary.json` sidecar, read back after the last draw call and before `Present()`. The software renderer needs no display, so this runs anywhere the game builds -- it is the first thing in the repository that actually looks at a frame. Split so the testable half is pure: `ScreenshotSummary`/`SummarizeScreenshot`/`ScreenshotLooksRendered` (`include/`/`src/Graphics/ScreenshotSummary.*`) live in `iron_gang_core` and need no device; `src/Graphics/ScreenshotCapture.*` in the executable is the only part that touches `GraphicsDevice`. Deliberately **not** a golden-image comparison -- `--smoke N` is not frame-deterministic, so a pixel hash would fail everywhere for reasons unrelated to rendering; the stable property is whether the frame is a rendered scene at all. New CTest `iron_gang_screenshot_capture_tests` runs the real binary and checks the PNG header and the sidecar; mutation-checked by making `Draw()` return straight after `Clear()`. See `docs/screenshots.md`, including what the first review of three captured frames found.)*
