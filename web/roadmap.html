Development Plan

Roadmap

27 milestones completed across two subsystems — the mature chunk/city generator, and a new planetary map subsystem (quadtree LOD, hydrology, mountains, biomes, settlements, countries). MAP9 is the active milestone; MAP10–MAP14 are planned.

✓ Completed ▶ In Progress ◇ Planned

✓ Completed Milestones

M1 — Core Foundation

WorldConfig, WorldMap, ZoneType, RegionType

JSON config loading, grid-based zone/region assignment, chunk coordinate system, world seed infrastructure.

M2 — Scene Builder

Mc3SceneBuilder + MC3Writer

Safe C++ API for constructing MC3 scenes. addBox, addCylinder, addPlane, addGround, addInstance, setMetadata.

M3 — Material System

MaterialRegistry — ~100 built-in materials

Full material catalogue with RGB, roughness, category, and license metadata. CLI tool MeshWorldMaterials.

M4 — C++ Generators

20 built-in chunk generators

ApartmentBlock, Beach, Bridge, Cave, Crossroad, Desert, Empty, Forest, Jungle, Meadow, Mountain, Ocean, Park, RiverBank, Road, ShopStreet, SmallHouseBlock, Square, Swamp, Tundra.

M5 — Chunk Pipeline

ChunkPipeline + ChunkCache

File-based disk cache, cache-first generation skip, Lua-first → C++ fallback dispatch.

M6 — MC3 Validation

MC3Validator

XML well-formedness, metadata presence, bounds checking, material name validation. ValidationResult with error list.

M7 — Lua Runtime

LuaRuntime + LuaSandbox

Lua 5.4 + sol2 integration. Sandboxed execution blocking io/os/debug/require. Scene API binding.

M8 — Lua Generators

LuaGeneratorRegistry + 17 Lua generators

Auto-discovery from generators/lua/. Park, forest, crossroad, road zones; bench, chair, door, fountain, fridge, lamp, table, trash_can, tree, tv, window objects; simple_house building; kitchen room.

M9 — Taxonomy

TaxonomyRegistry + ContainmentRuleRegistry

Node hierarchy from taxonomy.json. LOD-aware containment rules from containment.json.

M10 — Content Packs

SqliteContentPack + ContentPackLoader

Pack and load all generators, taxonomy, materials, and styles into a portable .sqlite file. MeshWorldPack CLI tool.

M11 — Style Registry

StyleRegistry + BuiltinStyles

Named style system mapping style strings to parameter sets. central_europe_small_city and others.

M12 — CLI Tools

MeshWorld, MeshWorldMap, MeshWorldExport

World info dump, ASCII zone map, bulk chunk export. MeshWorldExport --mcb flag for binary output.

M13 — Texture Registry

TextureRegistry

Texture entry registry (groundwork for atlas support in future milestones).

M14 — Generation Metadata

GenerationMetadata + ProceduralWorldGen

Structured metadata for generation context. ProceduralWorldGen utility class for seeded deterministic generation helpers.

M15 — Mc3DocumentBuilder

Mc3DocumentBuilder

Higher-level document builder wrapping Mc3SceneBuilder for programmatic MC3 construction outside of generators.

M16 — Mc3Renderer

Mc3MeshBuilder + Mc3Renderer + FPCamera

CPU tessellation of MC3 primitives to triangle meshes. First-person camera. SceneRenderer integration (guarded by MESH_WORLD_HAS_RENDERER).

M17 — World Streaming

WorldStreamer + WorldRenderer

Real-time chunk streaming around player position with configurable load radius. LOADED/UNLOADED callbacks. 127/127 streaming tests pass.

M18 — MeshWorldApp

Interactive 3D viewer + MainMenu

Standalone MeshWorldApp binary with WASD + mouse look, live chunk streaming, main menu system. Built on CNA (SDL3/OpenGL).

Planetary Map Subsystem (new, MeshWorld::Map)

MAP0 — Vertical Slice

Planet → LOD descent → SQLite → chunk hand-off

The one genuinely hard part proven cheap first: descend a coarse planet into one location and hand off to a rendered chunk. Green-light gate passed 2026-07-01 — descent is deterministic, edge-consistent, and fast enough to build on.

MAP1 — Coordinates & Tile Model

TileCoord — quadtree addressing

{level, x, y} tile coordinates with parent/child derivation and hashing, the addressing scheme for every level of the LOD pyramid.

MAP2 — SQLite Storage Foundation

MapTileStore

Per-level/region-sharded SQLite persistence for generated map tiles.

MAP3 — Planet Config & World Bootstrap

Planet-scale world setup

Bootstraps a planet-scale world alongside the existing chunk-scale world.json config.

MAP4 — Planet Generator (C++)

PlanetGenerator — level 0

C++ generator for the root tile: continents, coarse elevation/moisture via noise::fbm, biome seeding.

MAP5 — Naming Subsystem

Naming::country() / city() / mountain() / river()

Culture-aware procedural name generation, later reused by FeatureNaming (MAP8) and Countries (MAP9).

MAP6 — Lua Map-Generator Binding

MapBuilder / MapValidator / LuaSandbox::executeMap()

Mirrors the chunk system's Lua-first → C++ fallback pattern for the map layer. planet.lua is live in the real MapPipeline, not just exercised by tests.

MAP7 — LOD Descent & Constraint Propagation

Parent/child edge consistency

MapBuilder::setBiomeField() enforces parent edges as a fixed boundary condition; only "named" quadtree levels persist, others regenerate deterministically. continent.lua (level 3) and region.lua (level 7) added.

MAP8 — Hydrology, Biome & Terrain Refinement

Hydrology · MountainRanges · BiomeRefinement · FeatureNaming

Rivers traced downhill to oceans/lakes with confluence detection; entropy-driven mountain ridges with peak/pass profiles; coastal and swamp biome refinement; named MapFeature entries for all of the above. C++ generators only — not yet ported to the 3 Lua map scripts.

▶ Active & Planned

MAP9 — Active Milestone

Political & Settlement Layer

Chosen right after MAP8 finished. Done so far: Settlements.hpp data model (Capital/City/Town/Village), Settlements::place() suitability-ranked placement, Countries.hpp + Countries::grow() multi-source territory growth from capitals.

Neither is wired into the live pipeline yet — no storage field exists for a SettlementNetwork/CountryNetwork, and naming/persistence is still ahead.

Next up: borders that prefer natural features (rivers, ridges, coasts) over cutting across open terrain.
MAP9 (remainder)

Roads, Lua Ports, Naming & Persistence

  • Country borders prefer rivers/ridges/coasts over open terrain
  • Culture per country (Naming::country())
  • RoadNetwork connecting settlements
  • Lua ports: country.lua (level 5), metro.lua (level 9)
  • Naming + persisting settlement/country labels (mirrors MAP8's FeatureNaming)
MAP10 — Street-Level & Chunk Hand-off

Map Layer Drives Chunk Generation

city.lua (level 12, street grid + zoning) and neighborhood.lua (level 15, named streets). ChunkContext.map_context populated from MapPipeline so chunk generators read biome/elevation/roads from the map layer instead of the flat WorldMap.

MAP11 — 3D Model Store & Streaming

Geo + Altitude Indexed Placement

ModelPlacement store queryable by 3D proximity (horizontal + vertical radius), background-thread streaming as the player moves. Also unblocks the deferred cave-zone seeding from MAP8.

MAP12 — Zoomable Map UI

In-App Map View

ImGui-based zoomable/pannable map viewport with lazy tile loading, feature overlays (coastlines, rivers, borders), and level-of-detail-aware labels.

MAP13 — Validation & Tooling

MeshWorldPlanet Grows Up

--png/--ascii preview output, --stats (continents, land ratio, rivers, cities), --names, and a MapValidator CLI for validating a whole generated world.

MAP14 — Performance, Scale & QA

Benchmarks & Stress Tests

Cold vs. cached descent timing, async off-thread generation, LRU tile/DB caps, long-traverse memory stress tests, and a determinism check for regenerating deleted intermediate tiles.

Offline-first is a deliberate, final architectural decision — MeshWorld does not call any AI API at runtime, and no such integration is planned. AI tools are used during development to help write generators, not as a runtime feature.
