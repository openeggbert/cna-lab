Before lesson 1

Prerequisites

  • A C++23 compiler and CMake 3.25 or newer.
  • A local Explore2D checkout. CNA is not needed until lesson 23.
  • Comfort with structs, vectors, functions and basic CMake targets.
  • A new directory named signal-cabin beside explore-2d.
Course rule

Do not continue when a checkpoint fails. Each lesson assumes the previous room, ID and rule names remain exactly as written.

Module 1 · Lessons 01–04

Foundations

Establish the mental model, build graph and smallest valid world before drawing a detailed scene.

Lesson 01

Map the game as state changes

Outcome: a one-page design with four rooms, three required items and one winning condition.

Explore2D games are easiest to build when you describe progression before art. Signal Cabin will contain cabin, forest_path, generator and tower.

CABIN: talk to Mara → reveal gate key
FOREST PATH: collect patch cable
GENERATOR: install fuse + cable → power_on
TOWER: requires gate_open + power_on → win

Create these stable IDs now: items gate_key, patch_cable, ceramic_fuse; flags met_mara, key_revealed, gate_open, fuse_installed, cable_installed, power_on.

CheckpointYou can explain the complete winning route without mentioning rendering or CNA.
Lesson 02

Create the project skeleton

Outcome: a CMake project with a reusable world library and a scenario-test target.

signal-cabin/
├── CMakeLists.txt
├── src/
│   ├── SignalCabinWorld.hpp
│   └── SignalCabinWorld.cpp
└── test/
    └── ScenarioTests.cpp

Use the developer guide's CMake integration. Link signal_cabin_world publicly to Explore2D::Core. Do not add CNA yet.

add_executable(signal_cabin_tests test/ScenarioTests.cpp)
target_link_libraries(signal_cabin_tests
    PRIVATE signal_cabin_world)

enable_testing()
add_test(NAME signal-cabin.scenario
    COMMAND signal_cabin_tests)
CheckpointCMake configures with -DEXPLORE2D_BUILD_CNA=OFF and creates the test executable.
Lesson 03

Construct the smallest valid world

Outcome: buildWorld() returns one room that passes validation.

e2d::WorldDefinition buildWorld() {
    e2d::WorldDefinition world;
    world.title = "Signal Cabin";
    world.startRoom = "cabin";

    e2d::RoomDefinition cabin;
    cabin.id = "cabin";
    cabin.label = "SIGNAL CABIN";
    cabin.background = e2d::PaletteColor::blue;
    cabin.defaultSpawn = {32, 232};
    cabin.solids.push_back({0, 260, 492, 28});
    world.addRoom(std::move(cabin));
    return world;
}

In the test, call world.validate(), assert the error vector is empty, then construct AdventureSession and assert currentRoomId() == "cabin".

Checkpointctest reports one passing scenario test and the session starts in the cabin.
Lesson 04

Render the first headless frame

Outcome: a 640×350 frame exists before any desktop window is introduced.

auto world = buildWorld();
e2d::AdventureSession session{world};
e2d::AdventureRenderer renderer{world};

renderer.renderTitle();
assert(renderer.canvas().width() == 640);
assert(renderer.canvas().height() == 350);

renderer.render(session);
assert(renderer.canvas().bytes().size()
    == 640U * 350U * 4U);

The renderer is part of the core. It produces CPU-owned RGBA bytes from palette-indexed operations, making visual smoke tests possible without CNA.

CheckpointThe test renders both title and world frames and still runs with CNA disabled.
Module 2 · Lessons 05–08

Build the place

Turn the blank room into a readable cabin, support the player and connect the first screens.

Lesson 05

Learn the coordinate and palette contract

Outcome: a measured room sketch that fits the 492×262 viewport and uses only palette indices.

Room-local origin is (0,0); the renderer places it at framebuffer (8,8). The standard player is 14×28 pixels and stands at y = 232 on a floor beginning at y = 260.

using P = e2d::PaletteColor;

cabin.background = P::blue;
cabin.decorations = {
    e2d::RectVisual{{0, 210, 492, 50}, P::brown, true},
    e2d::LineVisual{{0, 210}, {491, 210}, P::brightYellow},
    e2d::TextVisual{{170, 30}, "SIGNAL CABIN", P::white, 2}
};
CheckpointNo world-definition code contains an arbitrary RGB value.
Lesson 06

Draw the cabin with reusable motifs

Outcome: a recognisable interior built from rectangles, lines, circles and text.

Create helpers such as addWindow, addDesk and addRadio. Each helper receives a room and origin, builds a Drawing, then appends its visuals.

e2d::Drawing radio;
radio.origin({330, 142})
    .rectangle({0, 0, 116, 92}, P::darkGray)
    .rectangle({8, 8, 100, 76}, P::black)
    .text({22, 16}, "RADIO", P::brightYellow)
    .circle({30, 54}, 9, P::lightGray, false)
    .line({50, 50}, {92, 50}, P::brightGreen)
    .line({50, 61}, {88, 61}, P::brightCyan);
radio.appendTo(cabin.decorations);
CheckpointThe cabin communicates “radio station” before any label or dialogue is read.
Lesson 07

Add support, platforms and movement tests

Outcome: the player stands on the floor, turns deliberately and can jump onto a low platform.

cabin.solids.push_back({0, 260, 492, 28});
cabin.solids.push_back({180, 218, 112, 10});

e2d::SessionConfig config;
config.turnBeforeWalk = true;
config.walkStep = 10.0F;

e2d::AdventureSession session{world, config};
session.walk(e2d::Direction::left); // first press turns
assert(session.player().facing == e2d::Facing::left);

Keep collision geometry simpler than decoration. The desk may use many visuals but only one solid top.

CheckpointA headless movement test confirms facing, position and grounded state after ticks.
Lesson 08

Connect the forest, generator and tower

Outcome: four rooms with explicit directional exits and sensible spawns.

Create the remaining rooms with distinct backgrounds and ground silhouettes. Connect cabin ↔ forest_path ↔ generator ↔ tower.

forest.exits.push_back({
    e2d::Direction::left, "cabin", {462, 232}, {}, {}});
forest.exits.push_back({
    e2d::Direction::right, "generator", {8, 232}, {}, {}});

generator.exits.push_back({
    e2d::Direction::right, "tower", {8, 232},
    {e2d::Condition::flag("gate_open")},
    "The locked service gate blocks the tower path."});
CheckpointValidation finds all exit destinations, and the blocked tower exit shows its message before the gate opens.
Module 3 · Lessons 09–12

Make it interactive

Add examination, collection, inventory use and deliberate overlap resolution.

Lesson 09

Create your first EXAMINE hotspot

Outcome: examining the cabin radio explains the immediate problem.

cabin.hotspots.push_back({
    "cabin_radio", "RADIO", {326, 138, 124, 100},
    e2d::HotspotKind::mechanism, {}, {}});

world.addInteraction({
    e2d::Verb::examine, "cabin_radio", std::nullopt, {},
    {{"The receiver has local power, but the tower returns only static.",
        e2d::MessageStyle::inspect}},
    {}, 0, ""});

EXAMINE first opens the nearby/inventory target choice, then confirms the selected rule. Your test should call performVerb(examine), assert choice mode, confirm and assert message mode.

CheckpointThe radio message appears and closes back to world mode.
Lesson 10

Collect the patch cable

Outcome: TAKE changes the pose, inventory and world artwork.

Add patch_cable to world items. Add a forest hotspot visible only while cable_taken is clear, with a small cyan cable visual.

world.addInteraction({
    e2d::Verb::take, "patch_cable_pickup", std::nullopt, {},
    {{"You coil the weatherproof patch cable.",
        e2d::MessageStyle::inspect}},
    {e2d::Mutation::addItem("patch_cable"),
     e2d::Mutation::setFlag("cable_taken")},
    10, "take_cable_once"});

The session automatically turns toward the hotspot and enters the temporary taking pose before returning to standing.

CheckpointThe item disappears from the room, appears in inventory and cannot be taken twice.
Lesson 11

Use the cable on the generator

Outcome: USE combines a carried item with a mechanism and consumes the item.

world.addInteraction({
    e2d::Verb::use,
    "blue_terminals",
    std::optional<std::string>{"patch_cable"},
    {e2d::Condition::notFlag("cable_installed")},
    {{"The cable bridges the blue terminals exactly.",
        e2d::MessageStyle::inspect}},
    {e2d::Mutation::setFlag("cable_installed"),
     e2d::Mutation::removeItem("patch_cable")},
    10, ""});

Add a zero-area scenery hotspot whose cable visual is conditioned on cable_installed. This makes the state change visible after the message closes.

CheckpointThe cable leaves inventory and remains visibly connected in the generator room.
Lesson 12

Resolve the key-on-desk overlap

Outcome: EXAMINE targets the desk while TAKE targets the revealed key inside the same region.

Add a large desk hotspot and a smaller gate_key_pickup hotspot inside it. The desk's first EXAMINE rule sets key_revealed; make the key visible only while that flag is set and key_taken is clear.

Explore2D's action-aware resolution prefers a hotspot with an applicable rule for the current verb. Do not “fix” the overlap by moving the logical areas apart; test the behaviour intentionally.

place(session, "cabin", {215, 220});
session.performVerb(e2d::Verb::take);
assert(session.hasItem("gate_key"));
assert(session.flag("key_taken"));
CheckpointThe overlap regression test proves the desk never swallows TAKE for its key.
Module 4 · Lessons 13–16

State and story

Turn isolated actions into a coherent puzzle chain and state-sensitive conversation.

Lesson 13

Unlock a conditional route

Outcome: the brass key opens the service gate and enables the generator-to-tower exit.

Create a service_gate mechanism at the generator's right edge. The USE rule requires gate_key, sets gate_open and optionally consumes the key.

world.addInteraction({
    e2d::Verb::use, "service_gate",
    std::optional<std::string>{"gate_key"},
    {e2d::Condition::notFlag("gate_open")},
    {{"The brass key releases the weathered lock.",
        e2d::MessageStyle::inspect}},
    {e2d::Mutation::setFlag("gate_open")},
    20, ""});
CheckpointThe same exit blocks before the rule and moves to the tower afterward.
Lesson 14

Reveal the fuse through exploration

Outcome: examining the parts cabinet creates a newly visible pickup.

Add parts_cabinet and a hidden fuse_pickup. The first high-priority cabinet rule sets fuse_revealed; a lower-priority fallback describes the now-empty shelf.

// First visit: priority 10, only while not revealed.
{e2d::Condition::notFlag("fuse_revealed")}
{e2d::Mutation::setFlag("fuse_revealed")}

// Fuse hotspot visibility:
{e2d::Condition::flag("fuse_revealed"),
 e2d::Condition::notFlag("fuse_taken")}

This is the core exploration pattern: observation changes state, and changed state makes a new action possible.

CheckpointThe fuse is absent initially, appears after EXAMINE and enters inventory after TAKE.
Lesson 15

Write a speaker-aware conversation

Outcome: ENTER near Mara alternates compact bubbles between her and the player.

Add a character hotspot caretaker with an interaction area around Mara's figure. Create a priority-10 first conversation conditioned on notFlag("met_mara"), followed by priority-1 state-specific reminder rules.

{
  {"Mara: The storm killed the tower feed.",
      e2d::MessageStyle::speech,
      e2d::MessageSpeaker::target},
  {"I found a cable on the forest path.",
      e2d::MessageStyle::speech,
      e2d::MessageSpeaker::player},
  {"Mara: Find the main fuse before throwing the lever.",
      e2d::MessageStyle::speech,
      e2d::MessageSpeaker::target}
}
CheckpointThe test advances line by line and observes target → player → target anchors.
Lesson 16

Gate the generator with compound state

Outcome: the main lever starts only after both repairs; otherwise it explains what is missing.

Create the successful priority-20 contextual rule with three conditions: fuse installed, cable installed and power not on. Create priority-10 “already running” and priority-0 warning fallbacks.

{e2d::Condition::flag("fuse_installed"),
 e2d::Condition::flag("cable_installed"),
 e2d::Condition::notFlag("power_on")}

{e2d::Mutation::setFlag("power_on")}
CheckpointTests cover missing-both, missing-one, successful start and already-running cases.
Module 5 · Lessons 17–20

Feedback and identity

Give Signal Cabin a title, selective motion, restrained sound and readable terminal states.

Lesson 17

Design the title screen

Outcome: an engine-owned NEW GAME / LOAD / QUIT screen with original Signal Cabin artwork.

world.presentation.title.subtitle =
    "A MOUNTAIN RADIO ADVENTURE";
world.presentation.title.byline =
    "AN EXPLORE2D GAME";
world.presentation.title.titleColors = {
    P::brightCyan, P::brightMagenta,
    P::brightYellow, P::brightGreen};
world.presentation.title.artwork = {
    e2d::RectVisual{{18, 82, 604, 145}, P::blue, true},
    e2d::CircleVisual{{548, 110}, 18, P::brightYellow, true},
    e2d::LineVisual{{80, 210}, {280, 86}, P::white}
};
CheckpointrenderTitle() produces original art while retaining the shared Explore2D menu flow.
Lesson 18

Add one loop and one action animation

Outcome: the powered tower beacon pulses and generator startup sparks once.

Add tower_beacon as autoplay + loop conditioned on power_on. Add generator_start as non-autoplay + non-loop, then append Mutation::playAnimation("generator_start") to the successful lever rule.

Use 6–8 ticks per beacon frame and 2–3 ticks per spark frame. Keep the rest of the forest, cabin and machinery static.

assert(world.room("tower")->animations.size() == 1);
assert(world.room("generator")->animations.size() == 1);
assert(session.animationElapsed("generator_start").has_value());
CheckpointFrame-selection tests show the beacon changing, and the startup animation expires after one pass.
Lesson 19

Compose the monophonic sound set

Outcome: title, menu, pickup, repair, warning, death and victory have distinct short cues.

world.addSoundEffect({
    "pickup", {{440, 1}, {660, 1}, {880, 2}}, 0.15F});
world.addSoundEffect({
    "warning", {{147, 2}, {110, 3}}, 0.16F});
world.addSoundEffect({
    "repair", {{880, 1}, {0, 1}, {880, 1}}, 0.13F});
world.addSoundEffect({
    "unlock", {{196, 1}, {247, 1}, {330, 2}}, 0.15F});
world.addSoundEffect({
    "victory", {{392, 2}, {523, 2}, {659, 2},
                {784, 2}, {1047, 6}}, 0.18F});

world.presentation.sounds.pickup = "pickup";
world.presentation.sounds.warning = "warning";
world.presentation.sounds.victory = "victory";

Now give the earlier cable/fuse rules the explicit repair cue and the gate rule the unlock cue through their final soundEffect field. Add equally short title, menu, death and save/load definitions to their presentation bindings. Keep volume around 0.10–0.20 and phrases under one second for frequent actions.

CheckpointCore tests observe queued effect IDs; later the CNA smoke test proves device playback.
Lesson 20

Create danger, death and victory

Outcome: one optional hazard route and a condition-gated final transmission.

Add a fallen bridge hazard to the forest side route. At the tower console, make the winning contextual rule require power_on and gate_open.

tower.hotspots.push_back({
    "relay_console", "RELAY CONSOLE",
    {305, 140, 150, 105},
    e2d::HotspotKind::mechanism, {}, {}});

world.addInteraction({
    e2d::Verb::context, "relay_console", std::nullopt,
    {e2d::Condition::flag("power_on"),
     e2d::Condition::flag("gate_open")}, {},
    {e2d::Mutation::win(
        "THE SIGNAL CABIN TRANSMITTER IS BACK ON THE AIR.")},
    20, ""});
CheckpointVictory and death enter distinct terminal modes, play their cues and restart cleanly.
Module 6 · Lessons 21–24

Test and ship

Protect progress, automate the complete route, add CNA and finish with a disciplined release pass.

Lesson 21

Verify save and restore

Outcome: a mid-puzzle snapshot round-trips without preserving transient presentation state.

const auto path = std::filesystem::temp_directory_path()
    / "signal-cabin-test.e2dsave";
std::string error;
assert(e2d::saveSnapshot(session.snapshot(), path, &error));

const auto loaded = e2d::loadSnapshot(path);
assert(loaded);

e2d::AdventureSession restored{world};
assert(restored.restore(*loaded.snapshot));
assert(restored.flag("cable_installed"));
assert(restored.hasItem("ceramic_fuse"));

Delete the temporary test save afterward. The real CNA host binds S/L to the path in HostConfig.

CheckpointRoom, inventory and flags survive; message mode, sounds and animations restart safely.
Lesson 22

Script the complete winning route

Outcome: one deterministic test proves the game remains finishable.

talk_to_mara(session);
reveal_and_take_key(session);
take_patch_cable(session);
unlock_service_gate(session);
reveal_take_and_install_fuse(session);
install_patch_cable(session);
start_generator(session);
activate_tower_console(session);

assert(session.mode() == e2d::SessionMode::won);

Write helpers in terms of public session actions: place via snapshot, call verbs, select inventory choices and dismiss messages. Do not set puzzle flags directly in the winning-route test.

CheckpointThe full route and a separate hazard → death → restart test both pass from clean sessions.
Lesson 23

Launch the real CNA host

Outcome: Signal Cabin opens in a resizable desktop window with audio and fullscreen.

e2d::cna::HostConfig host;
host.windowTitle = "Signal Cabin";
host.presentationScale = 2;
host.savePath = "signal-cabin.e2dsave";

e2d::cna::AdventureGame game{
    buildWorld(), {}, {}, host};
game.Run();

Configure with a complete CNA checkout via -DCNA_SOURCE_DIR=/path/to/cna. Play the real route once. Verify point-sampled scaling, F11 in both directions, title audio, pickup/repair cues, save/load and clean quit.

CheckpointThe executable reaches the title, begins a game, toggles fullscreen and produces sound.
Lesson 24

Run the release pass

Outcome: a small, complete, documented and reproducible Explore2D game.

  1. Configure a fresh headless build directory and run all tests.
  2. Generate title, each room, dialogue, TAKE pose and action-animation previews.
  3. Confirm every state change has a visible room consequence.
  4. Build against the complete CNA checkout and run a bounded dummy video/audio smoke test.
  5. Write controls, premise, build instructions, suggested route and license in README.
  6. Commit only source and intentional assets; keep build directories and saves ignored.
COURSE COMPLETEThe emergency signal is back on the air.

You now have the full pattern needed for a new Explore2D game: room → interaction → item → state change → room.
